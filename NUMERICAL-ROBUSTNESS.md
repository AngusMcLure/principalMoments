# Numerical robustness assessment and proposed work

Assessed version: **0.2.0, commit bd3fadc**. No package algorithms were changed
for this assessment. Results below are empirical limits on specific fixtures,
not universal limits or guarantees for other moment vectors.

Version 0.3.0 addresses several of these failures; see the
[implementation progress report](ROBUSTNESS-PROGRESS.md). The results below
remain the preserved baseline for version 0.2.0.

## Findings

The current implementation is not reliable for large moment sequences, and
there are also mixed-power failures at very small dimension. Returning a result
with small moment residuals does **not** establish accurate nodes, weights or
sharp bounds. The existing small-case tests do not detect these stress cases.

The most serious issue is that a small eigenvalue of a raw moment matrix can be
mistaken for an exact boundary moment sequence. The consecutive solver then
returns a single measure twice and erases genuine partial-identification
uncertainty. The generalized solver has this same issue when it dispatches to
the consecutive solver. Its nonlinear path also accepts approximations that
can have inaccurate target functionals despite small raw-moment residuals.

## What was tested

- 233 feasible fixtures, 38 additional tolerance runs, and 16 translated-support
  runs: **287 solver calls**. No runtime limit was reached; the longest individual
  main/tolerance run took approximately 3.4 seconds on this machine.
- Consecutive moments: orders 1 through 24 individually, then 28, 32, 40, 60,
  and 100, across six distributions. Independent reference values are available
  through order 32; no forward-accuracy claim is made for the higher orders.
- Fixed-size cases use Uniform Q, Beta(2,3) Q, Beta(0.2,0.2) Q,
  Beta(0.01,10) Q, and pooled Q=1-(1-P)^s generated by beta-distributed P with
  (p,rho,s)=(0.01,0.1,25) and (0.001,0.1,50).
- Mixed designs use their actual attainable subset-sum exponents, including
  repeated pools of sizes (2,3), (10,40), (25,26), and heterogeneous designs with
  up to 31 unique nonzero moments. Known principal measures give independent
  reference nodes, weights and target values for one side of each fixture.
- Additional mixed cases use the theory's Beta(0.09,8.91) prevalence distribution.
- Pool-size-only and exponent-scaling experiments separate moment dimension
  from total units. Tests on general translated support illustrate cancellation
  during raw-moment normalisation; the main pool-testing cases all use [0,1].

Reference moments and quadrature were calculated with Python mpmath at 100
**decimal** digits, and all 381 reference representation rows were recalculated
at 160 digits. Maximum change in functional values was 2.93e-75; maximum change
in nodes/weights was 1.72e-72. Rounded-to-double reference values agreed exactly.
The consecutive reference uses high-precision moment linear algebra; the mixed
reference constructs valid principal measures directly from known support
patterns, positive weights and rational nodes. Solver inputs are nearest-double
roundings of high-precision moments, so comparisons include both input rounding
and solver error. The precision comparison is a strong numerical cross-check,
not an interval-arithmetic proof.

Environment: R 4.5.0, Debian 13, IEEE double precision, machine epsilon 2.22e-16.

[raw results](benchmarks/robustness/results/runs.csv),

## Fixed pool size: empirical limit is about 11–16 moments, not hundreds

For this table, success requires the correct interior/boundary status and
reference node, weight and functional errors below 1e-6 in absolute units.
All the listed distributions are nondegenerate with interior moment vectors.
The default consecutive-solver tolerance is 1e-12.

| Moment source | Pool size s | Last order before the first problem | First problem |
|---|---:|---:|---|
| Q uniform | 25 | 16 | At 17: falsely returns a boundary measure |
| Q Beta(2,3) | 25 | 16 | At 17: falsely returns a boundary measure |
| Q Beta(0.2,0.2) | 25 | 16 | At 17: falsely returns a boundary measure |
| Q Beta(0.01,10) | 25 | 11 | At 12: falsely returns a boundary measure |
| P beta, p=1%, rho=0.1 | 25 | 16 | At 17: falsely returns a boundary measure |
| P beta, p=0.1%, rho=0.1 | 50 | 15 | At 16: falsely returns a boundary measure |

Warnings begin earlier (8–13 moments across these distributions). The rare-Q
case has very small functional errors even after the false-boundary
classification; that does not make the reported principal representations or
claim of a collapsed sharp interval correct. Conversely, the endpoint-singular
prevalence integrand can amplify inaccuracies substantially in other cases.

Concrete failures, expressed as individual-prevalence **percentages**:

| Case | Correct reference interval | Returned interval |
|---|---|---|
| Uniform Q, s=25, v=17 | [3.82447%, 4.71996%] | approximately [3.82261%, 3.82261%] |
| True p=1%, rho=0.1, s=25, v=17 | [0.960663%, 1.637627%] | approximately [0.959078%, 0.959078%] |
| True p=0.1%, rho=0.1, s=50, v=16 | [0.0868253%, 0.3297070%] | approximately [0.0864675%, 0.0864675%] |

In the two beta-prevalence examples, the returned collapsed interval excludes
the true prevalence. Residuals are only about 2e-13. This is a correctness
problem, not merely slow convergence. No algorithmic repair is included here.

There is no independent maximum pool size. In the fixed-Q formulation the
matrix dimension depends on v, while s enters the functional. Tests with
v=1,2,3 and s up to 10^12 succeeded on the uniform-Q fixture. This is a numerical
experiment, not a proposed biological design. If P is held fixed instead, s
changes the distribution of Q and can change conditioning. Stability also
depends on endpoint evaluation and representable input precision.

A conservative interim range is **v <= 10 for the six tested families**, with
warnings inspected and independent checks where accuracy matters. This is not
a distribution-free guarantee: even smaller moment problems can be arbitrarily
ill-conditioned. In the equal-size case v is the number of pools per location,
and the number of individual units is N=s*v; N alone is not a numerical limit.

## Mixed pool sizes: no safe cutoff based on dimension or total units alone

Let B=sum(v_a) be the total pools and N=sum(v_a*s_a) the total individuals per
location. The number of nontrivial moments is

```
d = number of distinct values of sum(r_a*s_a), 0 <= r_a <= v_a, minus one.
d + 1 <= min(product(v_a + 1), N + 1)     [integer pool sizes]
```

The maximum exponent is N. With common divisor g, there are at most N/g+1
possible orders including zero. Equal sizes give d=B; different sizes can
increase d greatly, but near-duplicate normalized exponents can also be poorly
conditioned even when d is tiny.

Selected examples at the generalized default tolerance 1e-9:

| Design per location | Pools B | Individuals N | Moments d | Observed behaviour |
|---|---:|---:|---:|---|
| One size-2, one size-3 | 2 | 5 | 3 | Both known-principal fixtures accurate |
| Three size-2, three size-3 | 6 | 15 | 13 | Known-principal fixtures accurate, but beta-prevalence fixture fails to converge |
| Four size-2, four size-3 | 8 | 20 | 18 | Mean/prevalence errors below 9e-9, but node errors up to 0.0174 |
| One size-10, one size-40 | 2 | 50 | 3 | Theory's beta example succeeds; a different valid known-principal lower fixture fails |
| Two size-10, two size-40 | 4 | 100 | 8 | Known lower fixture returned with prevalence error 0.0640 (6.40 percentage points) |
| One size-25, one size-26 | 2 | 51 | 3 | Known lower fixture returned with prevalence error 0.00255 (0.255 percentage points) |
| One size-100, one size-101 | 2 | 201 | 3 | Tiny moments accepted with errors up to 0.556 in prevalence |
| Sizes 2,4,8,16,32, one each | 5 | 62 | 31 | Consecutive-moment dispatch falsely collapses both known-principal fixtures |

These deliberately difficult known-principal distributions are valid fixtures,
not claims that every realistic population fails for these designs. They show
why there is no honest universal statement such as "supports 20 moments" or
"supports 1,000 mosquitoes". For the scaled-order fixtures, keeping the same
normalized exponents and moments allowed N up to 5,000,000 with tiny error in
the known-side prevalence value; the underlying distribution changes with the
scaling, so this is not a fixed-population design comparison.

Accuracy of the target prevalence and accuracy of the full representation must
be reported separately. In particular, a good target integral is not evidence
that all returned nodes and weights are accurate.

## Why the current implementation fails

1. **Raw monomials are ill-conditioned.** Hankel/localising matrices become
   nearly singular at surprisingly low orders. Cholesky whitening helps compute
   the eigenproblem after these matrices are formed; it does not remove their
   inherent sensitivity or the information already lost in input rounding.
2. **One tolerance does incompatible jobs.** It controls moment residuals,
   feasibility decisions and boundary rank. A small positive eigenvalue is
   treated as zero, producing unjustified point identification. Raising tol to
   1e-9 makes the uniform false boundary start at 14; the generalized API
   delegates equally spaced orders with this larger default tolerance. Lowering
   the consecutive tolerance to 1e-15 or
   1e-18 mostly produces explicit errors instead of recovering the lost range.
3. **Raw residuals do not control forward error.** The generalized solver uses
   absolute stopping/acceptance tests and a scaling floor of 1e-4. Small but
   informative moments can therefore be ignored. The map from moments to an
   unobserved first moment may be extremely sensitive.
4. **Generic nonlinear iteration is not a robust generalized quadrature
   algorithm.** Clipping steps can merge nodes or erase weights. Restarts are
   not continuation and do not diagnose rank, preserve a strict interior
   pattern, or certify extremality of an approximate solution.
5. **Endpoints and transformations amplify error.** For Q, the prevalence
   integrand has an unbounded derivative near one. Mapping X=Y^(1/s) and then
   computing 1-X can lose digits; use stable log/expm1 forms where possible.
   Raw-moment transformations of far-translated intervals also cancel badly:
   this benchmark fails for Uniform(10^6,10^6+1) at only four moments.
6. **Input precision is a fundamental limit.** For orders 100,101,201, these
   two distributions have exactly the same moments after rounding to double:
   (1/3)*delta_(1/3)+(2/3)*delta_(2/3), and
   (1/3)*delta_0+(2/3)*delta_(2/3).
   Their prevalences differ by 1/9, or 11.11 percentage points. The exact
   differences in their moments are about 6.47e-49, 2.16e-49 and 4.18e-97.
   Converting those already rounded doubles to arbitrary precision cannot
   recover this lost information.

Tighter tolerance sometimes helps a particular case, but is not a general fix.
For the size-(25,26) lower fixture it reduces error from 0.00255 at tol=1e-9 to
4.4e-9 at tol=1e-15, then fails at tighter tolerances. The size-(2,101) fixture
still has error 0.016 at tol=1e-15 with residual around 1e-18.

## Proposed solution, before major implementation changes

### 1. Make unresolved accuracy explicit first

Separate input uncertainty, feasibility tolerance, numerical rank threshold and
requested functional accuracy. A small eigenvalue must lead to an
"ill-conditioned / unresolved" status unless boundary structure is established;
it must not automatically collapse the interval. Check support pattern,
nonnegativity, node separation, conditioning, and relative as well as absolute
moment reproduction. Report residuals, forward-error estimates, precision used,
and whether full nodes/weights or just the target bounds appear stable.

Do not silently discard higher moments or project noisy moments to feasibility.
Any moment projection should remain a separate statistical operation. Existing
API calls can remain wrappers, but ambiguous results should fail safely or
return an explicit unresolved status rather than authoritative sharp bounds.

### 2. Preserve the available input information

Support high-precision decimal strings / MPFR inputs from the outset and
allow moment uncertainty intervals. Precision must extend through validation,
linear algebra, nonlinear iteration, node transformations and evaluation.
Converting final double outputs to MPFR is insufficient.

Add an optional direct input path for the location-count probabilities or
better-conditioned modified moments. For equal pools, the probabilities
integrate the Bernstein basis `choose(v,k)*q^k*(1-q)^(v-k)`; mixed joint counts
integrate products of corresponding basis functions. These span the same
identified function space as the selected monomials, but can avoid a damaging
intermediate conversion to raw powers. Redundant mixed-count constraints would
need a rank-revealing basis selection and consistent uncertainty handling.

For raw moments already supplied as doubles, distinguish the exact mathematical
problem for those numbers from the uncertainty about the intended moments.
Arbitrary precision can stabilise computation but cannot restore missing data.

### 3. Replace the consecutive backend with orthogonal-basis machinery

Use suitably scaled shifted orthogonal-polynomial / modified moments,
modified-Chebyshev or related stable recurrence construction, then a symmetric
tridiagonal Golub-Welsch calculation with Radau/Lobatto endpoint modifications.
Use recurrence/rank diagnostics rather than raw monomial null-polynomial roots
as the default boundary mechanism. Choose a reference basis near the measure
when possible and apply adaptive precision when required.

A change of basis alone is not magic: forming modified moments by cancellation
from rounded raw doubles can lose the very digits it is intended to protect.
Direct modified-moment input or sufficiently precise arithmetic is essential.

### 4. Replace generalized multistart fitting with structured continuation

Build the quadrature progressively by adding constraints through the ordered
Chebyshev system, tracking canonical/principal representations. Use an
orthogonalized/scaled function basis, ordered-node and positive-weight
coordinates or constrained trust-region steps, analytic derivatives and
rank-revealing QR/SVD. Handle approaching boundaries explicitly instead of
allowing clipping to decide effective support accidentally.

Normalise exponents, consider t=-log(X) (powers become exponentials), and use
stable exponential/divided-difference evaluations for large or nearly equal
orders. Adapt arithmetic precision based on conditioning and observed
convergence, not a fixed number of deterministic initial guesses.

### 5. Validate target bounds, not just quadrature residuals

Compare results after increasing arithmetic precision and record stability of
bounds separately from stability of nodes/weights. Add primal/dual checks:
construct generalized-polynomial minorants/majorants of the target functional
and verify their inequalities over the full interval. A dense grid is not a
certificate; rigorous mode would need root isolation or interval arithmetic.
Dual coefficient magnitudes also quantify how input-moment uncertainty affects
the bound. With uncertain moments, return conservative bounds for that
uncertainty set rather than falsely precise bounds for rounded numbers.

### 6. Set empirical targets and test them before advertising capacity

First fix the low-order silent failures in this report. Then target consecutive
orders 50 and 100 and generalized dimensions 25 and 50; extend toward 250/100
only if accuracy and runtime justify it. These are proposed benchmark targets,
not promised universal limits. Track exponent spread/max order, effective rank,
input precision, endpoint mass, relative prevalence error and certification
status. Include realistic rare-prevalence distributions and arbitrary known
principal measures. Use fast adversarial regressions in normal CI, with a
separate scheduled/manual high-precision stress workflow.

The main obstacle at present is conditioning and incorrect acceptance/rank
logic, not the small dense matrices' CPU cost. A robust mixed solver is a
substantive numerical-methods implementation, rather than a larger iteration
limit or a single dependency substitution.

## Suggested order of work

1. Fail-safe diagnostics and regressions for all silent failures above.
2. High-precision input contract and reference fixtures; stable endpoint evaluation.
3. Consecutive orthogonal/modified-moment backend with precision refinement.
4. Structured generalized continuation and explicit boundary handling.
5. Optional certified/uncertainty-aware bounds and broad stress CI.

This assessment implements **none of those solver changes**. It adds reproducible
experiments and this proposal so the scope can be reviewed first.

## Reproduction

From the repository root, with R and Python mpmath installed:

```sh
python benchmarks/robustness/generate.py
Rscript benchmarks/robustness/run.R
Rscript benchmarks/robustness/followup.R
```

The follow-up appends to `runs.csv`; run the main script first to reset it.
Default tolerances are unchanged. Per-case limits are 12 CPU / 15 elapsed
seconds; none was reached. `rules.rds` is a local intermediate, not committed.
For the higher-precision reference check:

```sh
ROBUSTNESS_DPS=160 ROBUSTNESS_RESULTS=work/reference160 python benchmarks/robustness/generate.py
python benchmarks/robustness/validate.py benchmarks/robustness/results work/reference160
```

## Sources informing the proposal

- The project's [mixed-pool theory](https://github.com/AngusMcLure/MX-PVS-sample-size/blob/clustered-group-testing-theory/clustered-group-testing-theory.Rmd)
  gives the identified exponent sets and principal-representation patterns.
- Gautschi, [On the Construction of Gaussian Quadrature Rules from Modified
  Moments](https://www.cs.purdue.edu/homes/wxg/selected_works/section_08/040.pdf)
  (1970), motivates modified rather than raw moments.
- Huybrechs, [On the computation of Gaussian quadrature rules for Chebyshev
  sets of linearly independent functions](https://arxiv.org/abs/1710.11244),
  develops incremental quadrature construction for complete Chebyshev systems.

The proposed combination of these methods, adaptive precision, uncertainty
handling and validation is an implementation plan, not a claim that these
references supply a drop-in robust solver for every input.
